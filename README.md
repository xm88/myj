# 浮岛旅团 V0.2.1

同一账号、同一个角色、同一张世界。PC 浏览器里走路、打怪、契约灵兽；手机或窄屏用「助手」收派遣、看拍卖和公会。战斗、掉落、经验和金币都由服务器计算。

这一版把灵兽养成和战斗场面再收一档。召唤兽可以合灵、用兽纹帖指定一招或覆掉旧招，也能用捕兽索野捕。出手有飘字和短读条，旅人、召唤兽、对手分成三列。任务追踪带进度条，小地图能分清自己、门、摊和任务。新号有可跳过的三步：进镇、接兽、首战。回合结算、掉落、门和同伴 AI 没改。

召唤兽和宠物分开用。召唤兽出战之后会在回合里单独出手，有根骨、长势、兽技、信赖和元息。宠物继续给光环，也能派出去。造型仍是页面里的矢量图。

地图上的旅人、镇民和怪物各有体型、配色和部件。界面是旅团自己的漆木金边：世界铺满，左上头像和血法，右上小地图，右边名册，底下技能和聊天，对话沉在下方。没有借用别的游戏的图或名字。

装备可以用火砂淬炼，失败不毁装备。同伴听稳打、猛攻、照应或集火。商店能筛选和一次买几个，任务日志写着报酬。顶栏看得到下一候，氛围底噪可以关掉。回合、掉落、税和门没改。

上一版的壳还在：对话台词在羊皮纸上，地图名字带等级或类型小标，底栏收着技能、灵伴、守势和背包、任务、地图、助手。出手顺序用头像排开。助手里派遣、拍卖、公会是卡片。天气和时段会轻轻染一下画面。系统开了「减少动态效果」时，呼吸、走路和别的动效会停。

网页这一版是暖色羊皮纸和木框。背包、对话、技能栏、摆摊和当面交易用同一套。血条、技能、过图和窗口有短动效。系统开了「减少动态效果」时，这些动效会停。玩法仍由服务器结算。

设计来源是《浮岛旅团》第一版落地方案：星落镇、翠叶森林到古代遗迹、武器即职业、半即时战斗、灵伴契约与派遣、制造、5% 税的拍卖行、简化公会。这一版先把这条循环做成能玩的垂直切片，而不是把大型 MMO 的城战、抽卡和跨服一起做进来。

## 跑起来

```bash
npm install
npm run dev
```

服务端使用 Go 1.25 或更新版本。请先安装 Go 并加入 PATH；也可以设置 `GO_BINARY` 指向 Go 可执行文件。项目内若有 `.tools/go/bin/go.exe`，启动脚本会自动使用它。Node.js 只用于 Vue 前端、npm 启动脚本和客户端回归脚本。

浏览器打开 http://127.0.0.1:5180 ，点「游客进入」。

- 游戏服务：http://127.0.0.1:8787
- 网页：http://127.0.0.1:5180 （`/api` 和 `/ws` 会转到游戏服务）
- 数据库文件：`data/float-island.sqlite`（已在 `.gitignore` 里）

`npm test` 跑 Go 公式、账号、事务回滚、拍卖并发、派遣、仓库和 WebSocket 测试。`npm run export-config` 校验 `config/*.json`；配置表现在是服务端直接读取的源数据。升级记录见 `CHANGELOG.md`。

也可独立启动服务端：

```bash
cd server
go run .
go test ./...
go build -o ../bin/float-server .
```

`npm run build -w server` 生成 `bin/float-server`（Windows 上是 `bin/float-server.exe`）。运行二进制时保留项目的 `config/` 目录，或设置 `FLOAT_ROOT` 指向项目根目录。`PORT` 默认 8787；`FLOAT_DB` 可指定 SQLite 文件。Go 源码改动后重启服务，前端仍由 Vite 热更新。

## 密钥和部署

开发时可以不设置 `JWT_SECRET`。服务会使用内置默认密钥，并在日志里警告一次。这个默认值只为了本机能玩，不要放到公网。

`NODE_ENV=production` 时必须自己设置 `JWT_SECRET`：至少 16 个字符，而且不能是开发默认值。令牌是 HS256，十四天过期。仓库不生成、也不提交真实密钥。变量名见 `.env.example`。

登录、注册和游客入口按 IP 限流。本机限额更宽。密码哈希在世界锁之外计算，避免一次登录把 100ms 战斗循环卡住。服务如果跑在反向代理后面，先设置 `FLOAT_TRUST_PROXY=1`，才会相信 `X-Forwarded-For`。

同一个角色被第二个窗口连上时，旧窗口收到 `replaced`，然后停止重连，避免两个窗口互相挤掉。

## 怎么操作

- 点地面、地名、人或传送门走路。走近后按 E，或点名字后面的按钮。右上角小地图看这一带，左下角是坐标。顶上是生命、法力和经验
- 1–4 技能，F 携带者的灵技，G 守势。底栏右侧还能开背包、任务、地图和助手，快捷键写在格子上。点怪物会走近并开战：按速度轮流出手。轮到你时中间亮出攻击、技能、物品、防御、逃跑；轮到召唤兽时是攻击、兽技、防御。出手顺序是一排头像。连招会在轮到你或召唤兽时自动攻击。对话左边是立绘，数字键和 Enter 选事项，Esc 离开
- 右边的任务追踪分主线和支线，点一条就会过去。背包里的装备可以和身上的对比
- 契约要先把可契约的目标打到 30% 血以下，并消耗灵契球。七成血以下可以用捕兽索野捕，套住的兽还不熟。灵兽窗口里可以出战、休息、喂食、刻印、兽纹帖和合灵
- 走到地图边上的门会进入下一片，落在对面门内侧。镜头保持连续，小地图跟着世界坐标，不再整张切掉
- 摆摊：站定后开摊、标价上架，旁边或界边的人可以来买。成交扣和拍卖一样的旅税。收摊把剩下的东西退回背包
- 当面交易：点附近旅人的名字打开双栏，放入物品或金币，两边锁定后再确认
- 右上角「助手」切到手机布局。助手状态下角色不会挨打
- 开发模式（不是 `NODE_ENV=production`）里，派遣可以按「测试：立刻完成」，不用干等

短途侦察是 1 分钟的测试档，产量只有一小时基准的 0.08。正式挂机用半小时、两小时、四小时、八小时。

## 目录

```
server/*.go    Go 游戏服务。账号、世界、战斗、灵伴、背包、拍卖、公会在同一个进程里
server/src     旧 TypeScript 实现和迁移回归脚本，默认启动不执行这里的服务端
web/src        Vue 3 冒险界面和助手
config         Go 服务端直接读取的 JSON 配置表
docs           架构、玩法、接口、表结构、新手流程
```

修改 `config/*.json` 后，运行 `npm run export-config` 检查引用和重复 ID，再重启 Go 服务。旧版 `server/src/content/` 仅保留为迁移参考，不再作为运行时数据源。

## 和方案文档的差别

方案里的运行时是 Unity + Go + PostgreSQL + Redis。服务端已从 TypeScript 迁移到原方案的 Go，保持模块化单体和现有 REST / WebSocket JSON 协议。账号、角色、世界、战斗、灵伴、背包、市场和公会逻辑在 Go 进程内执行。客户端仍是 Vue；数据库暂时保留兼容已有存档的 SQLite，使用纯 Go 驱动，不需要 C 编译器。PostgreSQL 和 Redis 尚未接入，PostgreSQL 建表仍在 `docs/sql/001_postgres.sql`。

客户端和服务器之间第一版用 JSON，不使用 Protobuf。消息名字是固定的：`input`、`target`、`skill`、`capture`、`interact`、`snapshot`。以后给独立客户端换编码，不必改玩法。

还没做、并且按方案应留到后面的：30 人团本、跨服、城战、复杂 PvP、野外闲逛的 AI NPC、UGC、坐骑、房屋、赛季、真实充值。星晶商店没有开。回合里的队友已经由同伴 AI 出手。大地图按成对的门拼在一起，镜头可以同时看见相邻地块；副本仍然单独进入。
