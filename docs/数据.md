# 数据

运行时是 SQLite。表按账号、角色、物品实例、灵伴、派遣、任务、拍卖、公会、邮件拆开。角色等级和坐标在 `players`，攻击防御不落库，穿脱装备时现算。装备的品质和词条在 `player_items.extra`。

对应的 PostgreSQL 写法在 `sql/001_postgres.sql`。两边的列名一致，迁的时候主要是把 JSON 文本改成 JSONB。

## 表

| 表 | 存什么 |
| --- | --- |
| users | 邮箱、密码哈希、是不是游客 |
| players | 名字、等级、经验、地图、坐标、血蓝、金币、当前武器、技能栏、标记、buff |
| player_tracks | 武器熟练和生活技能。`weapon:bow`、`life:gather` 这种键 |
| player_items | 背包、仓库、已装备。可堆叠材料 `extra` 为空；装备一行一件 |
| player_pets | 已契约的灵伴、等级、是否主战 |
| pet_dispatch | 派遣。`running` 直到领取，到点不自动发奖 |
| player_quests | `active` / `turned_in` 和进度数组 |
| market_orders | `open` / `sold` / `cancelled`，商品快照和标价 |
| guilds / guild_members | 等级、经验、公告；一个人只能在一个公会 |
| mail | 标题、正文、附件。没附件的信创建时就算领过 |
| friends | `pending` / `accepted` |
| chat_messages | `world`、`map:地图`、`guild:公会` |
| world_state | 天气和下一条传闻 |

## 物品实例

```json
{ "quality": "blue", "affixes": [{ "id": "crit", "name": "暴击", "stat": "critRate", "value": 0.02 }] }
```

模板 id（例如 `wpn_bow_4`）全世界共用。玩家手里那一件的 id 是单独的 uuid。拍卖上架时把模板、数量和 extra 拍进订单，再从背包删掉；取消或买下时按快照发还。

## 任务进度

`progress` 是和目标一一对应的整数数组。收集目标在接任务时会先数背包里已经有的数量。击杀只记接任务之后的。`reach_level` 记 0 或 1，不记等级本身。

主线的 `next` 在交付后自动接下一个。等级不够或线索标记还没有时，任务留在委托人那，条件够了再出现「接受」。

## 配置

源数据在 `config/*.json`。Go 服务启动时会检查重复 ID，以及地图刷新、传送门、掉落、灵伴技能、任务 NPC、配方和派遣点的配置引用。对不上就不起服。

`npm run export-config` 保留原命令名，现在运行 Go 配置校验。直接修改 JSON，再校验并重启服务，即可应用新的游戏数值。`server/src/content/` 是旧版迁移参考，不参与运行。
