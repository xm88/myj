# 架构

V0.1.5 是 Go 进程里的模块化单体。地图上的人再多，也先不要拆成十个服务。默认 npm 启动命令执行 Go 服务端；Node.js 用于网页开发和客户端回归脚本。

```
浏览器 Vue
  ├─ REST /api     档案、背包、派遣、制造、拍卖、公会、邮件
  └─ WebSocket /ws 移动、选目标、技能、契约、互动、聊天
        │
        ▼
   Go game server
     account / player / world / combat / pet / inventory / market / guild / quest
        │
        ▼
   SQLite（在线时血量和坐标在内存，金币和物品马上落库）
```

## 服务器权威

客户端只说「我想做什么」：

- 往哪个方向走、点了哪只怪、按了哪个技能槽、对谁用灵契球
- 不上传伤害、掉落、经验或金币变化

服务器每 100ms 推进一步：夹紧移动速度、结算普攻和怪物 AI、广播快照。快照里有坐标、血量、伤害数字和冷却，没有背包。背包变化时服务器发 `dirty`，网页再拉 `/api/profile`。

角色分人族、魔族、仙族，创建时选定。每级自动成长 5 点，人族五项各 1，魔族偏体力和力量，仙族偏魔力和耐力。另外每级 5 点潜力自己加。一点换成面板的比例也按族：魔族血和伤害更高，仙族魔法和防御更高。元素技能会加上灵力，物理普攻不加。结算在 `server/formula.go` 和 `inventory.go`。

防御减伤和伤害公式在 `server/formula.go`：

```
damage = attack × coefficient × (1 - defense / (defense + 500)) × elemental × crit
```

元素系数最低 0.2，避免堆抗性把伤害打成 0。

## 在线状态和数据库

人在线时，坐标、血量、蓝量、护盾、冷却放在内存里的 `LivePlayer`。金币、物品、灵伴、任务、派遣结束时间在 SQLite。金币和物品在变更时立刻写库，所以拍卖和领取不会因为每秒存档而丢。坐标大约每 5 秒，以及断线时，写回角色表。

断线后角色在世界里再留 60 秒，这段时间不会挨打。超时后从分线拿掉，下次连接按数据库里的地图和坐标回来。

## 地图分线

每张野外和城镇仍是一条分线里的一块地图，一张公开地图一条线最多 20 人，满了开下一线。古代遗迹按队伍队长（没有队伍就按自己）单独开一份副本，人走光就拆掉，下次再进是新的。

相邻地图如果互相有门，会按那两扇门对齐到同一套世界坐标。人走到门的外侧，就在对面门的内侧落地，不会被拉回入口。快照里的 `chunks` 把当前地块和这些邻块的原点发给网页，镜头按世界坐标一起画。站在界边时，对面靠近门的人、怪物、摊位和 NPC 仍按缝隙计算距离。副本和航标仍是整图进入：航标只能在星落镇用。古代遗迹的镜头里没有外面的大陆。

回合战斗在 `server/bout.go`，队友的出手在 `server/companion.go`。摆摊和当面交易在 `server/stall.go`、`server/trade.go`。摆摊成交扣 `marketTax`，和拍卖是同一个比例。过界和镜头地块在 `server/chunk.go`。

## 天气和时段

全服一份天气，默认每 8 分钟换一种，存在 `world_state`。时段按东八区的真实钟点分成早晨、白天、黄昏、夜晚、深夜。

它们会改这些事：

- 雷暴提高雷属性怪物攻击，并让雷鸣矿掉落概率翻倍
- 血月让怪物攻击略高
- 雨天提高森林猫的契约率，并额外刷新森林猫
- 夜晚才刷月光猫；大雾刷雾狐；晴天白天更容易看到火狐
- 星潮提高金色史莱姆的出现率

## 模块对照

| 方案里的服务 | 这一版的文件 |
| --- | --- |
| Account | `player.go` 的注册、登录、游客、JWT |
| Player | `player.go`、`inventory.go`、`profile.go` |
| World | `world.go` 的分线、移动、天气；`actions.go` 的互动 |
| Combat | `formula.go`、`world.go` 的 `hurtMonster` / `hurtPlayer`；`actions.go` 的技能 |
| Pet | `pets.go` |
| Inventory | `inventory.go` |
| Market / Guild / Chat | `economy.go` |
| Task | `quest.go` |

`main.go` 管理 HTTP、WebSocket 和 100ms 游戏循环；`http.go` 保留网页现有 API。HTTP 请求、WebSocket 命令和游戏循环通过同一把互斥锁串行修改世界状态。密码哈希在拿锁之前完成，避免登录拖住这一拍。每条 WebSocket 只有一个写协程，慢客户端不会阻塞游戏循环；大约 15 秒一次心跳，大约 45 秒没有回应就断开。经济写入使用数据库事务，失败时恢复内存状态（包括事务中途新增或删掉的在线角色），通知在提交后发送。没人的野外分线再空闲 90 秒就卸掉，下次进入按配置重新刷怪。副本仍然是人走光就拆。SQLite 使用 WAL，表结构、bcrypt 密码、HS256 JWT 和毫秒时间戳兼容旧版。

战斗、采集、拍卖各自只发一个事件，例如 `{ type: 'kill', monsterId }`。任务模块自己决定要不要记进度，战斗代码不用知道任务表。
